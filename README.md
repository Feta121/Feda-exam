# Anesthesia Mock Exam

A question bank and timed mock-examination site for anesthesia students, built from four PDF question books
(about 3,000 questions, plus a Word document of seniors' questions). React + TypeScript + Vite + Tailwind. It runs entirely in the browser and can optionally
use Supabase for student accounts, synced results and shared admin edits.

## Quick start

```bash
npm install
npm run questions   # builds public/questions.json from data/question_bank.json
npm run dev         # http://localhost:5173
npm test            # 52 tests: scoring, randomisation, timer, auto-submit, reload persistence, practice, analytics, admin
npm run build       # type-check + production build into dist/
```

## What is in the app

Dashboard · Sources (first page of each book, its titles, and practice by title) · Mock exam (20/30/50/75/100/all questions, custom duration, random or by subject or from your wrong
answers or bookmarks) · Practice where clicking an option shows the result straight away · Subjects and topics · Weak-area analysis · Bookmarks and
wrong answers · Exam history with full review and "repeat this exam" · Admin (edit, add, hide, import, export,
duplicate review, extraction report) · light and dark theme · desktop sidebar and mobile bottom navigation.

Exam rules: 5 questions per page by default (you can pick 1, 2, 3, 5, 10 or 20 on the setup screen), navigator with answered / unanswered / flagged states, countdown that is
computed from a fixed end time (a reload cannot reset it), automatic submission at zero (also if the page is
reopened after time has run out), confirmation before manual submission, answers and explanations hidden until
submission, progress saved after every action. Answer options are shuffled only when that cannot change their
meaning (lists such as "all of the above", numeric scales and matching questions keep their order).

## About the questions and their answers

* 2,217 playable questions use the answer key printed in the PDFs or the Word document.
* 787 questions (all from the Arba Minch PDF) had no key. Their answers and explanations were generated by an AI
  model, are labelled "AI-generated" in the app, carry a confidence rating, and have **not** been verified by a
  person. Students can exclude them on the exam setup screen. Please review them (Admin -> Show: "AI-generated
  answers"; the 112 Low-confidence ones first) and mark them verified once checked.
* 1,017 explanations were AI-written (787 for the Arba Minch questions, 200 for EHPLE, 30 for matching questions);
  the other explanations come from the books.
* 24 questions are excluded from exams because their options are missing or are in a figure in the PDF
  (see `data/extraction_report.json` and Admin -> Show: "Needs a figure"). Fix them in Admin to bring them back.
* Subjects for A Comprehensive Review and Lippincott's follow the books' chapters. Arba Minch and EHPLE have no
  headings, so their subjects come from keyword rules and have not been reviewed question by question.
* Exact and likely duplicates are kept in the bank but an exam never contains two copies of the same question.

## Administration

* **Local mode (no Supabase):** set `VITE_ADMIN_PASSCODE` when building. Edits are stored in that browser only, and
  the passcode is visible to anyone who reads the built JavaScript, so treat it as a convenience, not security.
  In `npm run dev` the passcode defaults to `admin`; production builds have admin disabled unless you set one.
* **With Supabase (recommended):** run `supabase/schema.sql`, set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`,
  sign up in the app, then make yourself an admin with the SQL at the bottom of the schema file. Row-level security
  lets everyone read edits but only admins write them, and students can only see their own results.
  This integration was written against the Supabase API but has not been run against a live project.

## Deploying for free

* **Netlify / Cloudflare Pages / Vercel:** build command `npm run build`, publish directory `dist`.
  Or drag the prebuilt `dist/` folder onto Netlify Drop.
* **GitHub Pages:** push to `main`; `.github/workflows/deploy.yml` builds and publishes it. Add the three
  `VITE_*` values as repository secrets if you use them.
* The site uses hash routing, so no server rewrites are needed.

## Updating the question bank

1. **Small additions:** Admin -> Import / export -> import a JSON array
   (`{"question","options":{"A":"..."},"answer":"A","explanation","subject","topic"}`), or use Add question.
2. **Publishing edits for everyone without Supabase:** Admin -> Export full bank, replace `data/question_bank.json`
   (keep the same field names), run `npm run questions`, rebuild and redeploy.
3. **New PDFs:** the scripts in `pipeline/` are the ones used for these four PDFs. They are written for those
   specific layouts (paths point at text dumps made with `pdftotext`/PyMuPDF), so a PDF with a different layout
   needs a new parser modelled on `parse3.py` (simplest) or `parse4.py`. Keep the output fields
   (`question, options, answer, explanation, flags`) and run `finalize.py` to merge, classify and flag duplicates.
   Never guess an answer key: leave it empty and it will be marked unverified.

## Project layout

```
data/        question_bank.json (full extraction output), extraction_report.json
public/      questions.json (generated, what the app loads)
pipeline/    extraction, merge, duplicate-detection and AI-answer scripts used to build the bank
scripts/     build-questions.mjs
supabase/    schema.sql (tables and row-level security)
src/lib/     exam.ts (pool, shuffle, session, scoring, timer), analytics.ts, storage.ts, cloud.ts
src/state/   AppContext.tsx
src/pages/   Dashboard, ExamSetup, ExamRun, Results, Practice, Subjects, Weak, Saved, History, Admin
```

## Tested / not tested

Automated (all passing): scoring by original option key with shuffled options, no repeated questions inside an
exam, different random exams, pool filters and duplicate handling, countdown arithmetic, auto-submit at zero,
auto-submit on reopening an expired exam, reload persistence of answers/flags/position/timer, hidden answers
during the exam, review after submission, practice feedback, weak-area and wrong-answer tracking, bookmarks,
admin gating and persisted edits.

Not tested: real-browser rendering and mobile layouts (the layout uses responsive Tailwind classes but was not
viewed on actual devices), Supabase against a live project, and the correctness of the extracted questions beyond
the automated checks and the flags listed above.
